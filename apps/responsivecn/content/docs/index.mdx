A centered Dialog is hard to use on a phone. The shadcn docs [combine Dialog and Drawer by hand](https://ui.shadcn.com/docs/components/base/drawer#responsive), so each project rewrites that code and the same bugs come back: cast types, overwritten `className`s, lost callbacks, duplicated children. **responsivecn** ships it as installable components that follow the shadcn conventions: open code, a registry install, compound components.

A **pair** is a curated desktop→mobile combination. Each pair produces a **responsive component**: a drop-in replacement for the desktop component that renders the mobile one below the [breakpoint](/docs/breakpoint). Three pairs exist:

| Pair             | Responsive component                    |
| ---------------- | --------------------------------------- |
| Dialog → Drawer  | [`DialogDrawer`](/docs/dialog-drawer)   |
| Sheet → Drawer   | [`SheetDrawer`](/docs/sheet-drawer)     |
| Popover → Drawer | [`PopoverDrawer`](/docs/popover-drawer) |

## Bases

Each component works on **Base UI** (shadcn's default) and **Radix**, whichever shadcn base you installed. It is one file built on your own shadcn components (`@/components/ui/dialog`, `drawer`, …), so its props are those of your Dialog, Sheet or Popover. **React Aria** is not supported yet: its shadcn components have a different part structure, so a drop-in replacement cannot map onto them.
